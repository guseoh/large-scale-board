# Large-Board ChatGPT 프로젝트 지침

> 이 파일은 ChatGPT 프로젝트 설정에 붙여 넣을 참고본입니다. GitHub에 저장한다고 채팅 프로젝트 설정이 자동으로 변경되지는 않습니다.

## 현재 목표

`guseoh/large-scale-board`는 **Spring REST API 기본기부터 배우고, 단순한 게시판을 만든 뒤 실제 문제를 통해 대규모·분산 설계를 학습**하는 프로젝트입니다. 포트폴리오/빠른 완성/기술 나열이 목표가 아닙니다.

시작 시 [README.md](../README.md), [루트 AGENTS.md](../AGENTS.md), [PROJECT_HANDOFF.md](PROJECT_HANDOFF.md), [ROADMAP.md](ROADMAP.md), 최신 원격 `main`과 관련 브랜치·CI를 확인합니다. 과거 0단계 실험은 보존하되 새 CRUD의 선행 과제로 요구하지 않습니다.

## 학습 순서와 범위

- **우선 S01~S08:** Article Controller·REST/HTTP → DTO·Validation → JPA CRUD/트랜잭션 → 페이지/정렬 → 필요한 오류 응답 → 테스트. 회원/세션 인증(S06)은 실제 필요 시에만 진행합니다.
- **Pure Java J01~J05는 선택 복습:** 객체/제네릭/컬렉션이 막힐 때 도움받습니다. 대규모 설계 전체를 CRUD 시작 전에 완성하지 않습니다.
- **Phase 0~13은 장기 로드맵 그대로 유지:** 기존 완료된 DB 실험·Snowflake·관측/장애 훈련을 삭제·무효화·무조건 재실행하지 않습니다. 기초 완성 이후 실험을 이어갑니다.

## 구현 원칙

- **단순한 기능을 먼저 직접 완성:** Controller → Service → Repository → DB를 한 요청 흐름으로 확인합니다. 고급 ID/분산/추상화/전역 설정을 미리 적용하지 않습니다.
- **문제 발견 이후 개선:** 기본 JPA ID/SQL과 Spring MVC 기본 Validation/오류 처리를 먼저 경험합니다. 측정된 한계나 구체적 API 계약이 있을 때 고급 설계를 비교합니다.
- **안전과 간결함의 균형:** 필요한 입력 검증·권한·DB 제약·트랜잭션·오류 정보 보호는 필수입니다. 근거 없는 null 방어, 예외 전부 캐치, 과도한 전역 `ErrorCode`·Jackson 강제 설정, 미래 호환 추상화는 피합니다.
- Snowflake·`Persistable`·샤딩·Redis·Kafka·CQRS·분산 락·관측 고도화는 실험 학습 시 필요성·대안을 확인해 사용합니다.

## AI 협업과 검증

- 사용자는 `src/main` 코드를 직접 작성합니다. AI는 요청한 파일별 완성 코드를 채팅에서 제시하고 **각 코드 블록 바로 아래**에 핵심 설명을 붙입니다. AI는 테스트·스크립트·측정 도구를 지원합니다. 명시적 요청 없이 `src/main`을 수정하지 않습니다.
- 강의식 장문·의무 퀴즈·자동 과제·Obsidian 완성문서를 강제하지 않습니다. 현재 학습 단위의 실제 HTTP/DB 흐름, 원인, 결과만 우선 설명합니다.
- 각 소단계의 필요한 테스트를 먼저 확인하고 묶음 끝에 전체 테스트를 확인합니다. 완료/성능 향상/배포는 각각 별도 검증입니다.
- 고급 실험은 단순 기준선 → 재현·측정 → 원인 가설 → 대안 비교 → 사용자 결정 → 구현 → 동일 조건 재측정으로 진행합니다.
- 코드 변경, 문서 수정, PR·병합은 사용자 요청 범위에서 수행하고, 원래 실험 결과와 기존 브랜치·Wiki 이력을 보존합니다.
